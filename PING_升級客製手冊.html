0. 客製分層總覽

層內容改動位置需 build？
品牌識別App 名稱／圖示／splash／配色（62 處青綠→橘）／About／對話框圖示／捷徑native + 圖檔名稱配色要；圖檔免

功能修正精靈連動、線材槽數、metadata 頁首、檔名佔位符…native要
核心觀念（坑 #3）：先判斷改的是「資源檔」還是「原生 code」。資源檔（resources/profiles/**、resources/web/**、resources/images/**、resources/i18n/**）改完同步 portable 立即可測、免 build；原生（src/**、version.inc、CMakeLists.txt）要 CI build 約 50 分鐘。效率原則：native 改動批次化、湊齊一次 build。

★ 升級流程：基於新版 OrcaSlicer 再做一套

總原則：資源與工具鏈整包搬（幾乎零成本），native 改動逐類重套（行號會漂移，用函式名定位）。預估工時：resources 半天可跑起來；native 視上游變動 1–3 天＋數輪 build。
STEP 1建 repo 與分支：fork 新版 OrcaSlicer（如 v2.4.x）→ 開 ping/v4.0 分支 → 立刻把 PING_CUSTOMIZATION.md、PING_HANDOFF.md、本手冊複製過去。
STEP 2資源整包搬（免 build、先讓參數系統活起來）
  • resources/profiles/PING.json＋resources/profiles/PING/ 整夾（含床 STL、封面、貼圖）
  • resources/images/ 的 PING 資產：OrcaSlicer*.ico/.png/.svg（換內容保檔名）、printer_preview_PING_*.png、splash_logo*、PING_about*、info.svg、question.svg
  • resources/web/ 客製：guide/21,22,24,4orca、data/text.js、homepage logo
  • resources/i18n/**/*.mo（含 PINGSlicer.mo 副本）＋ .gitignore 例外 !resources/i18n/**/*.mo
  • tools/ping/ 整夾（embed_params.py 等）→ 跑 python tools/ping/embed_params.py 重生驗證
  • ⚠ 保留上游 OrcaFilamentLibrary.json（啟動必需，坑 #2）；移除其他廠商 vendor 時別動它
STEP 3品牌 native（第一輪 build 前）：version.inc／libslic3r.h／CMakeLists.txt(CPack/捷徑)／src/CMakeLists.txt(執行檔名)／OrcaSlicer.rc.in／desktop 檔。配色 62 處：對新版重新全域搜 #009688/#26A69A/#52c7b8 等青綠色值替換（上游可能加了新 UI，處數會變）。
STEP 4去 Bambu native：GUI_App.cpp 四處 early-return＋on_init_network＋更新器。注意上游可能重構過這些函式——用函式名搜，照 B 節語意重套。
STEP 5功能修正 native 重套（D 節表格逐條）：嘗試 git cherry-pick 8df074a8 03610af9 5a191f95 dd1242e9 e496f8cf 4eb0162b…，衝突的用「函式名＋關鍵字」人工定位重寫。先確認上游是否已自修（例如新版 Orca 若已修 wxString 比對或槽數同步，就不用套）。
STEP 6CI workflow：build_orca.yml（PING_Slicer 檔名 glob／artifact 名）、check_profiles.yml（只看系統驗證）、build_appimage.sh.in（圖示）。
STEP 7build 與驗證：gh workflow run "Build all" --ref ping/v4.0（~50 分；坑 #10：Unit Tests 紅 X 是既有問題、Linux/Flatpak 偶發 Docker flake——看各平台編譯 success 即可）→ gh run download 取 portable → 跑下方驗證清單。
STEP 8發布：gh release create vX.Y.Z 附 installer＋繁中 release notes；同步更新 PING_CUSTOMIZATION.md（AGPL §5 要求記錄修改）。

關鍵坑 Top 10（完整 16 坑見 PING_HANDOFF.md §2）

  1. 設定精靈是 WEB（resources/web/guide/），不是 ConfigWizard.cpp。
  2. OrcaFilamentLibrary.json 是啟動必需檔——刪了會崩潰。
  3. 資源免 build／原生要 build——native 批次化一次 build。
  4. 改 profile 要 PING.json version +1，且同步兩處（portable resources＋%APPDATA%\PINGSlicer\system）。
  5. 中文機型名 ≠ wxString：native 比對一律 std::string（locale 轉碼會把中文變空字串）。
  6. inherits 絕不可空字串——整包 vendor 載入中止。
  7. app 找 PINGSlicer.mo，CI 不產 .mo——編譯好的 .mo 要收進 repo。
  8. 封面/縮圖以機型名與 model_id 解析檔名——機型改名要同步改圖檔名。
  9. 中文路徑會讓 shell 亂碼——批次處理用 Python。
  10. build 紅 X 先看哪個 job——Unit Tests 既有失敗、Docker Hub 偶發 flake，各平台編譯 success 就能用。

已知未解與待辦（接手詳見 PING_HANDOFF.md §0）

  • splash 真透明：素材是去背的；黑底＝native 合成鏈 alpha 丟失。修法方向：跳過 wxGraphicsContext，PNG 直組 premultiplied BGRA 餵 UpdateLayeredWindow，動態文字用已知底色區塊貼入。
  • FD 雙料/FF 四色偶發閃退：未定根因（「Invalid T command」僅候選）；每次發生記操作步驟對 log。
  • B7 批次：實體列印設備預設名帶機型（PhysicalPrinterDialog「- 複製」）／對話框大 logo 改小放左上／主機類型清單瘦身（只留 Octo/Klipper＋Moonraker）／參數端套 Scarf＋單料頭速度後移除 embed override。
  • 麥金塔：.app bundle 名與 dmg 檔名仍為 OrcaSlicer。
  • 工具列 title logo：OrcaSlicerTitle.png 需 PING 橫式 wordmark。

AGPL 合規要點（每一版都要守）

  • 保留 LICENSE.txt（AGPL-3.0 不變）；About 標註「Based on OrcaSlicer」＋源碼公開連結（§13）。
  • PING_CUSTOMIZATION.md 記錄所有修改（§5「prominent notices」）；保留上游版權與傳承段落。
  • 不可寫 "All Rights Reserved"；不打包／不下載 Bambu 閉源 DLL（無散布授權）。
